## Documentation rules

- Document current behavior and link to the source of truth when behavior is generated by code or migrations.
- Mark planned work as planned; do not describe a route or integration as live until it is wired and verified.
- Keep secrets, production exports and customer data out of documentation and Git.
- Use lowercase kebab-case filenames for new documents.
