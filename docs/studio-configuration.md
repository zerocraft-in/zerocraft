# Studio content and configuration

The public studio pages reuse the existing sections, logo, fonts, theme tokens, and animation libraries.

- `lib/data/studio-projects.ts` contains editable project metadata. The current entries are concept explorations with existing illustrative Unsplash images; they do not assert client relationships or outcomes. Replace with approved project assets and credits when available.
- `lib/studio-config.ts` preserves the existing business email and production domain. `NEXT_PUBLIC_SITE_URL` can override the canonical origin for a deployment.
- Instagram is confirmed by the supplied studio profile. LinkedIn, Behance, and GitHub use the exact profile URLs provided by the owner. X remains optional: set `NEXT_PUBLIC_X_URL` to the studio's exact HTTPS profile URL if one is confirmed. Unconfigured links remain hidden; platform names alone are not profile links.
- The contact form validates a brief and opens a `mailto:` draft. It does **not** transmit or store submissions. Sending directly from the website requires a server-side email provider, credentials, and abuse protection. Until configured, users send from their own email client or use the displayed email address.
- The admin MVP extends the existing Supabase studio at `/studio` with store orders, staff access, reports, and optional AI drafts. Apply [`supabase/admin-mvp.sql`](../supabase/admin-mvp.sql) to the configured Supabase project and set the variables listed in [`.env.example`](../.env.example). This SQL has not been applied by the code change itself.
- The store is a **concept catalog**. Sample product descriptions and estimated prices still need owner review; invented testimonials, ratings, policy promises, and placeholder contact details are not displayed. The checkout accepts **Cash on Delivery order requests** only. It never takes card details or claims payment succeeded. The server recalculates catalog prices and writes orders using `SUPABASE_SERVICE_ROLE_KEY`; when that key or the table is absent, checkout shows a failure and retains the cart. Customer-facing order history is a local browser copy, not live status tracking. Review catalog items, inventory, shipping rates, tax, currency, and fulfillment policy before opening the store to real buyers. The store is excluded from indexing until that review is complete.
- Staff start as `client` accounts. An administrator can promote registered users on `/studio/staff`; roles are enforced by the studio proxy and database RLS. Never expose the service-role key to the browser.
- Gemini drafting on `/studio/ai` requires `GEMINI_API_KEY` and a supported `GEMINI_MODEL`. Output is a human-reviewed draft and is not published automatically. Google AI Studio free-tier access and quotas vary by account/model; see [Google's pricing](https://ai.google.dev/gemini-api/docs/pricing).
- Appointment WhatsApp automation requires `N8N_WHATSAPP_WEBHOOK_URL` using HTTPS. Without it the UI reports that automation is unavailable; it does not simulate a successful send.
- The redesigned dashboard and `/studio/database` read live counts through an authenticated, uncached server endpoint. Missing tables and denied access appear as unavailable instead of zero. The source project was observed to have `appointments`, `blogs`, `clients`, `notifications`, `profiles`, `reviews`, and `works`, but no `store_orders` at implementation time.
- For store orders, apply `supabase/admin-mvp.sql` in the connected project and supply `SUPABASE_SERVICE_ROLE_KEY` on the server. Order status and payment status can then be managed by studio staff. The reports page counts only orders explicitly marked paid as paid order value; it is not a payment processor settlement report.
- For queued automations, apply `supabase/studio-automation.sql` **after** the admin migration. It creates a deduplicated event table and triggers on new orders and appointments. Configure `STUDIO_AUTOMATION_WEBHOOK_URL` as an HTTPS endpoint, `SUPABASE_SERVICE_ROLE_KEY`, and `CRON_SECRET`. Schedule a POST to `/api/studio/automations` with `Authorization: Bearer <CRON_SECRET>` every minute (or another suitable interval). The studio admin can also dispatch manually. The receiver should deduplicate using the `Idempotency-Key` header. The payload includes only event and minimal order/appointment metadata; it does not include customer addresses or contact details. Webhook acceptance is recorded, not downstream message delivery. Failed dispatches back off and retry up to five times. No workflow runs without those settings.
- `/studio/ai` uses Gemini for blog, project, social, product, and customer-reply drafts. It does not publish or send output. Without `GEMINI_API_KEY` and `GEMINI_MODEL` the page reports configuration missing. Do not enter customer personal data in prompts.
- Run `npm run lint`, `npm run typecheck`, and `npm run build`. On Windows machines where Turbopack workers fail to start, `npm run build -- --webpack` is the supported fallback.
- `node scripts/generate-og.js` regenerates the social preview using the existing Zerocraft mark.
